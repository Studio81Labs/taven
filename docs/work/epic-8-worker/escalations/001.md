# Escalation 001: profile-bundle provenance re-lock

- Status: RESOLVED
- Parent Epic: #8
- Implementation issue: #113
- Discovered in: #109
- Resolution: [GitHub issue #116](https://github.com/Studio81Labs/taven/issues/116)

Replacing locale-sensitive profile ordering with UTF-16 code-unit ordering
changes the serialized provenance manifest and its bundle digest. The approved
resolution authorizes a bounded re-lock of that provenance digest only:

- `profiles/manifest.json` is regenerated;
- `profiles.bundleSha256` is updated in the runtime lock and corpus baselines;
- resolved profile bytes, the OCI digest, and the invocation digest remain
  unchanged.

This is a determinism correction, not an Orca engine or profile-content
upgrade. Re-escalate if any resolved profile changes, OCI digest drift occurs,
or a corpus baseline changes outside `profiles.bundleSha256`.
