# RESOLVED — validated automatic-quote handoff for assisted requests

Status: **RESOLVED**. Resolution date: 2026-09-07.
Decision: [ADR 0011](../../../decisions/0011-use-single-use-automatic-quote-handoff-capabilities.md).

The original escalation is retained below. RESOLVED means implementation is
unblocked; it does not mean PR #89 has implemented the correction or passed
review.

## Context

PR #89 replaces arbitrary public attribution with the approved normalized
channel/source/medium/campaign contract. The existing assisted-quote web flow
previously placed an `automaticQuoteHandoff` object inside attribution. Codex
review correctly identified that removing the arbitrary object also removes
the sanitized automatic-quote session ID, model IDs, selections, and handoff
reasons which the operator needs when assessing the assisted request.

## Discovered gap

The browser-held handoff context contains foreign automatic-quote identifiers,
but no transferable capability proof. The existing `QuotesService` cannot
validate that the caller is authorized to disclose or link that automatic
quote session. Reintroducing the object as a dedicated field would therefore
persist foreign IDs based only on client input.

## Conflicting assumption

The prior web implementation assumes its browser-side sanitization is enough
to make the handoff safe. The approved implementation plan §6.5 requires
foreign IDs to be validated against the caller's capability or principal before
insertion. The proposed normalized-attribution contract deliberately rejects
the previous arbitrary payload.

## Why implementation cannot safely continue

The handoff needs a public API and security-boundary design: whether the
automatic-quote capability token is presented to the assisted-request command,
or the source service mints a short-lived, single-use, scoped handoff
capability. That choice determines the persistence model, replay semantics,
expiry behavior, OpenAPI contract, and cross-customer privacy guarantees.

## Options

1. Require the existing automatic-quote bearer capability with a structured
   handoff field, and validate the source session, expiry, and selected IDs in
   the quote-request transaction.
2. Add a server-minted short-lived, single-use handoff capability bound to the
   automatic quote session and safe context; the assisted-request command
   consumes it atomically.
3. Explicitly stop transferring automatic-quote context and update the UI and
   product copy to require manual re-entry.

## Concrete decision required

Choose the authorized handoff mechanism and its expiry/replay semantics, or
approve removing automatic-quote context from assisted QuoteRequests.

## Resolution

Choose option 2: a server-minted, opaque, short-lived, single-use
`ASSISTED_QUOTE_REQUEST` capability. The existing automatic-quote bearer
capability is required to mint it; it is never passed to the assisted request.
The source service validates the bearer, source session, current server-owned
draft and handoff-eligible state, then snapshots only the bounded allowlisted
context needed by operators. The token has a 15-minute maximum lifetime,
clamped to the source automatic session expiry.

The assisted create command receives only the opaque token in a dedicated
top-level request field (`automaticQuoteHandoffToken`). Normalized attribution
remains limited to channel/source/medium/campaign. The quote-request
transaction locks and consumes the handoff row, validates scope and expiry,
and persists a typed server-derived handoff record linked to the source
automatic session and new request. Client-provided session IDs, model IDs,
selections and reasons are never accepted as evidence.

Issuance is idempotent for the same source session, bearer capability and
idempotency key; replay returns its original stored issuance response even if
that token was consumed, while a changed fingerprint conflicts. A successful assisted-create
replay returns the stored result without consuming again. A different command
key cannot reuse a consumed token. Expired, missing and invalid capabilities
produce a generic capability failure without source existence or context
disclosure. If request creation fails, the transaction rolls back consumption.
Consumption is terminal after a successful request.

The browser may retain its sanitized context only for local copy and UI
prefill. The server-issued handoff token is the sole authority for linking the
automatic quote. Existing contexts without a token fall back to manual entry.

## Rationale

The existing automatic bearer is deliberately broader and reusable: it powers
session polling, observations and draft mutations. Reusing it at the assisted
request boundary would couple two public capabilities and make replay scope
depend on the 30-day source session. A dedicated capability follows the
existing capability model while narrowing the privilege to one disclosure and
one assisted request.

Server minting is necessary because the browser-held IDs are foreign to the
assisted request. The automatic quote service is the authority that can verify
the IDs and derive reasons from the current draft and findings. Persisting its
immutable snapshot preserves what was actually disclosed even if the source
draft later changes or expires. The 15-minute bound limits stale handoffs while
allowing navigation and form completion; clamping to source expiry prevents a
handoff outliving its source authority.

Atomic database consumption gives deterministic replay behavior across tabs,
retries and concurrent submissions. Keeping the token outside attribution
preserves the approved normalized marketing contract and prevents arbitrary
JSON from becoming a foreign-identifier channel. Generic invalid/expired
responses avoid turning the assisted endpoint into a source-session existence
oracle.

## Rejected alternatives

1. **Option 1: reuse the existing bearer.** Its privilege is broader than the
   handoff needs, it is reusable, and it makes assisted-request expiry and
   replay semantics depend on a long-lived source session.
2. **Option 3: remove the context.** Manual re-entry discards a useful v0
   assisted flow even though a scoped capability can preserve privacy and
   operator provenance.
3. **Client-supplied structured handoff or sanitized IDs.** Shape validation
   cannot prove possession or ownership and permits cross-customer linkage.
4. **Reusable signed/JWT handoff.** A signature proves issuer authenticity but
   does not provide a durable single-use replay fence.

## Required implementation changes

1. Add a source automatic-session handoff command guarded by the existing
   session bearer. It needs an idempotency key, generic unauthorized/expired
   behavior, a 15-minute bounded expiry, and a server-derived allowlist of
   source session ID, model-file IDs, item selections and canonical reasons.
2. Add a forward migration and Prisma models for an opaque token hash,
   capability scope, source session, issued/expiry/consumed timestamps,
   issuance idempotency identity and consumed request; add the immutable typed
   request-handoff record or relation. Token plaintext is response-only.
3. Extend `CreateQuoteRequestDto` with the opaque token field, keep it outside
   `AttributionDto`, and make `QuotesService.createRequest` consume it inside
   the existing idempotency transaction. Lock before checking consumed state;
   rollback must leave the token available after any failed request.
4. Derive and persist the handoff snapshot from the locked capability. Add a
   typed operator projection for the source session/reasons/selections without
   exposing bearer tokens, arbitrary JSON, contact data or storage keys.
5. Update the web configurator and assisted form: request the handoff token
   through the source endpoint, store only the opaque token for submission,
   preserve local context only for copy, clear token/context after successful
   submission or expiry, and fall back to manual entry when minting fails.
6. Regenerate OpenAPI/client output and update the attribution tests so unknown
   handoff fields remain rejected. Do not reintroduce `automaticQuoteHandoff`
   under attribution.

## Required tests and validation

- Minting requires a valid source bearer and matching session; foreign,
  missing, expired and malformed capabilities fail without context leakage.
- The server snapshot ignores tampered browser IDs/reasons and reflects the
  source draft/findings at mint time. No contact data, raw storage key or
  bearer token is persisted.
- Handoff lifetime is at most 15 minutes and never exceeds source expiry;
  source expiry, handoff expiry and cleanup paths are covered.
- Two tabs/concurrent creates with the same token produce at most one request;
  a successful idempotent retry returns the original response without a second
  consume, while a different idempotency key is rejected.
- Failed validation or transaction rollback leaves an unconsumed handoff;
  successful consumption is terminal and source-session mutation/expiry cannot
  reopen it.
- Cross-customer/session attempts cannot attach another session's context;
  errors reveal no source existence, model IDs or reasons.
- Attribution accepts only the normalized fields; the token is top-level and
  generated OpenAPI/client types match runtime validation. Existing manual,
  blocked-3MF and no-file flows remain unchanged.
- PostgreSQL migration tests cover token-hash uniqueness, scope/FK integrity,
  immutable snapshot/consumption fields and rollback. Run fresh and upgrade
  migrations, backend/web tests, generated checks, lint, typecheck, build and
  the P5 assisted-flow E2E with real dependencies; skipped database tests do
  not count as passing.

assisted-flow proof into P5.
