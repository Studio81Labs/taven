# RESOLVED — bound automatic-quote handoff capability issuance

Status: **RESOLVED**. Resolved 2026-09-07 by [ADR
0011](../../../decisions/0011-use-single-use-automatic-quote-handoff-capabilities.md).

## Resolution

Choose option 1 with a strict one-row lifetime bound: a source automatic-quote
session may have at most one `AutomaticQuoteHandoffCapability` row, whether the
capability is later consumed or expires. A new idempotency key while that row
is unconsumed and unexpired returns the existing handoff ID and derives the
same opaque token. The token remains hash-only in the database; the handoff ID
is already sufficient for the existing deterministic token derivation and
issuance response replay.

After the capability is consumed or expires, no replacement may be issued,
including after the source session remains within its 30-day lifetime. An
expired, unconsumed row is retained as immutable issuance evidence and is not
deleted by expiry cleanup. The caller uses the manual assisted-request flow.
This bounds anonymous issuance at one permanent capability row per source
session and preserves the consumed snapshot required for provenance.

The database must enforce the bound with a unique source-session constraint.
The issuance transaction must lock the source session and existing capability
row before deciding whether to replay the active capability or reject the
request. The current token-hash uniqueness and immutable trigger remain in
force.

## Rationale

The current command creates a new immutable row for every unique idempotency
key, so possession of one valid anonymous source bearer permits unbounded
database growth without creating a request. One row per source session gives a
hard, auditable bound without introducing a product-specific quota or a
deletion exception. The 15-minute handoff lifetime and manual fallback provide
an explicit recovery path when a browser abandons or delays the assisted flow.

Reusing an active row is safe because the token is derived from its opaque
handoff ID, while the database continues to store only its hash. No plaintext
or encrypted token material needs to be retained. The source session's 30-day
expiry does not reopen issuance.

## Rejected alternatives

- **Fixed multi-row quota:** rejected because it still permits avoidable
  permanent rows and adds an arbitrary owner-approved number without a
  demonstrated need for multiple handoffs. A one-row lifetime bound is
  stronger and simpler.
- **Replace after expiry and delete expired unconsumed rows:** rejected
  because it weakens the immutable issuance-evidence policy and requires a
  separate deletion and retention audit design. Expired rows are retained.
- **Keep unlimited issuance:** rejected because it leaves the anonymous
  resource-exhaustion vulnerability unresolved.
- **Stop transferring automatic-quote context:** rejected as the default
  because the validated capability design preserves the assisted flow. Manual
  entry remains the fallback after the single capability is unavailable.

## Required implementation changes

1. Add a forward migration and Prisma constraint making
   `source_quote_session_id` unique on
   `automatic_quote_handoff_capabilities`. The migration must preflight and
   abort on duplicate source-session rows; it must not delete or merge
   immutable evidence. Keep the existing token-hash uniqueness and immutable
   update/delete trigger.
2. Change `createHandoffCapability` so the transaction locks the source
   session and its capability row, returns the active row for a different
   idempotency key, and rejects issuance when the row is consumed or expired.
   Preserve same-key idempotent replay, fingerprint conflicts, generic expiry
   errors and source-bearer authorization.
3. Keep the capability row's allowlisted snapshot and token hash immutable.
   Do not add plaintext or encrypted token storage. The response may derive the
   token from the stored handoff ID using the existing key ring.
4. Update the OpenAPI description and web behavior so an exhausted or expired
   handoff explicitly falls back to manual assisted entry. Regenerate tracked
   clients after the contract change, if any.
5. Do not add a replacement cleanup job for these rows. Any future legal
   retention change requires a separate architecture decision and evidence
   migration; it is outside this correction.

## Affected issues and phases

- **Epic #7 / #24, P4 / PR #89:** implement the bounded issuance correction
  together with the automatic-quote handoff endpoint, quote-request consumer,
  generated contract and web consumer.
- **P5:** include the bound, concurrent issuance and manual-fallback cases in
  the integrated security and migration proof before #24 closes.
- **#20:** no automatic-quote pricing or source-session behavior changes
  beyond the new one-capability issuance bound.
- **#7 plan:** the automatic-handoff amendment in §6.5, migration guidance,
  issue mapping, tests and architecture-resolution record must be updated from
  the prior unlimited-issuance wording.

## Required tests and migration checks

- Fresh and upgrade migration tests verify the unique source-session
  constraint, duplicate preflight failure, token-hash uniqueness, foreign
  keys, and immutable update/delete protection.
- Command tests prove that one source bearer plus many unique idempotency keys
  yields one row and the same active token; concurrent issuance also yields one
  row; a changed fingerprint still conflicts.
- Boundary tests prove that consumed and expired capabilities cannot be
  replaced, including after source-session expiry, and that expired rows remain
  present.
- Existing handoff tests remain green for source authorization, 15-minute and
  source-expiry clamping, server-derived snapshots, atomic consume/rollback,
  same-key replay, alternate-key rejection after consumption and cross-customer
  privacy.
- Web and generated-contract tests verify manual fallback when no usable
  capability is returned. No production code or migration is authored by this
  resolution.

## Resume point

Implementation can resume at **issue #24, P4 / PR #89**, before the handoff
endpoint and quote-request consumer are treated as complete. Apply the
forward unique-constraint migration and service transaction correction first,
then regenerate and verify the API/web consumers, and finally run the P5
integrated matrix. The previous unlimited second-handoff rule in ADR 0011 is
superseded by this resolution.
