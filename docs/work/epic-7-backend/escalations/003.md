# OPEN — bound automatic-quote handoff capability issuance

Status: **OPEN**. Discovered during PR #89 review on 2026-09-07.

## Context

ADR 0011 authorizes issuing another single-use automatic-quote handoff
capability with a new idempotency key until the 30-day source session expires.
PR #89 persists each capability's immutable allowlisted snapshot and rejects
its deletion so a consumed request retains provenance.

## Discovered gap

A caller holding one valid anonymous source-session bearer can use unique
idempotency keys to create an unbounded number of immutable capability rows.
The existing per-session automatic-quote creation limit does not constrain this
new public command. An attacker can therefore create permanent database growth
without creating an assisted request.

## Conflicting assumption

ADR 0011 states that issuing a second handoff with a new key is allowed until
source expiry. The implementation and migration make each issued row
non-deletable. Those two choices are incompatible with a bounded public
resource lifecycle.

## Why implementation cannot safely continue

The correction changes capability issuance and lifetime semantics at a public
anonymous security boundary. It must establish whether a consumed or expired
handoff can be replaced, and if so the hard per-session bound and evidence
retention behavior. Choosing a quota or changing immutable-record cleanup
without an approved decision would change ADR 0011's explicit replay and
issuance semantics.

## Options identified

1. Permit one handoff capability per source session. Reuse its unconsumed,
   unexpired token for later issuance keys; after expiry or consumption the
   caller uses the manual assisted flow.
2. Permit a fixed owner-approved per-session issuance quota. Reuse a current
   unconsumed token, then allow replacement only until the quota is exhausted;
   preserve every issued immutable record.
3. Permit replacement after expiry but delete only expired, unconsumed rows.
   This requires changing the immutable-record policy and defining deletion
   evidence, while consumed provenance remains retained.

## Concrete decision required

Choose one option, including the numeric quota if option 2 is selected, and
state whether an expired unconsumed capability may be replaced. Update ADR
0011 with the chosen lifecycle before implementation resumes.
